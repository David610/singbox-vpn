Scope of the device evidence (read before relying on "Device acceptance: PASS"): the maintainer reported on 2026-10-11 that YouTube Shorts and long videos play in the native iPhone YouTube app through Hiddify over both VLESS+REALITY and Hysteria2. That test ran against the production exit while it was still on v1.1.0 binaries with the same Google-egress hairpin rules applied by hand. It was not repeated on the rc.5 build. The rc.5 exit was additionally verified server-side: 6/6 consecutive Shorts through the real REALITY tunnel with a Chrome iPhone-emulated browser, `profile-title: Arcana VPN` served, `vpn-admin doctor --protocol --require-protocol` passing.

UNVERIFIED: the Hiddify profile name "Arcana VPN" on a real device; cellular and Wi-Fi/cellular handover; a 15-minute sustained session; reconnect after a server reboot; reachability from a censoring network; real-device Hysteria2 on the rc.5 build.

Notes: This release fixes YouTube Shorts through the VPN. Root cause: YouTube's media server refuses Shorts video to specific datacenter egress IPs (Evolus AS215120 91.244.71.165 and Hetzner AS24940 62.238.46.190 were refused, Selectel AS50340 135.106.178.167 was accepted) while the player API still reports OK. The fix routes the Google/YouTube domain set from the exit through a dedicated outbound on the accepted IP, rejects literal-IPv6 Google destinations, fails closed, and adds the profile title "Arcana VPN" served to Hiddify. Invariants that must keep holding: docs/YOUTUBE_FIX_INVARIANTS.md. Cloudflare WARP is explicitly not part of the solution. Earlier RCs in this cycle were rejected by this process: rc.1 (updater from v1.1.0 could not start the new unit and had no reserved probe principal), rc.2 (update deadlocked on its own global lock), rc.3 (acceptance: IPv6 AAAA check on the disposable host and stage 13 start-limit budget; run 38141161861), rc.4 (passed once, run 38143514053, but failed intermittently when vpn-expiry-reconcile.timer raced the SIGKILL stages; runs 38141554751 and 38144309495), rc.5 (accepted). The AAAA record for the acceptance host was removed because the host's IPv6 neighbour discovery breaks after a reboot; that is an environmental issue of that Hetzner host, not of the release.
