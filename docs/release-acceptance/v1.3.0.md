Scope of the device evidence (read before relying on "Device acceptance: PASS"): the maintainer tested the subscription, the REALITY link and the Hysteria2 link in Hiddify on an iPhone against the exact v1.3.0-rc.1 install, reported that they work and that random YouTube Shorts play, and accepted the release on that basis. The per-cell native matrix (REALITY and Hysteria2, each on Wi-Fi and on cellular) was not recorded cell by cell.

UNVERIFIED: device and client versions (iPhone/iOS, Hiddify and its embedded core, YouTube, TikTok); which transport was exercised on which network; ten consecutive Shorts including a specific one; long-form playback with seeking and a 15-minute session; TikTok native and TikTok web; subscription refresh; idle, handover and IPv6/leak behaviour on the device; the phone's recovery after the server reboot; update transition from the published v1.2.0 to the final stable tag through the real GitHub release (covered instead by the three in-place transitions above); reachability from a censoring network; native iPhone recovery over IPv4 after a rejected literal-IPv6 flow (`reject_google` closes the flow; recovery is a client property).

Known limitations:
- Hosts updated from v1.2.0 keep the distribution's default nginx site listening on TCP/80; `vpn-admin doctor` warns. It was not reachable from outside with the default host firewalls, and renewal works with it present. Fresh installs disable it.
- The lifecycle harness supports AlmaLinux only; Ubuntu 24.04.5 was exercised with equivalent stages run by hand.
- A hosting IP that YouTube refuses cannot play Shorts without a hairpin to an accepted IP; this is per egress IP and not a defect of the release.
- A Hysteria2 client on one workstation network timed out at the QUIC handshake against the owner's exit while a client on another network passed; the cause was not investigated.

Notes: This release adds the standalone exit literal-IPv6 policy (`[egress] ipv6_literal = allow | reject_google | reject_all`, default `allow`), a downgrade guard that refuses a v1.2.0 updater run on a host that declares the policy, installed-release identity checks in `vpn-admin doctor`, and read-only commands that exit quietly on a closed pipe. Scope is the VPN product only; the Arcana website, billing and Tamara are deferred and untouched. No credentials, subscription tokens, private keys or links are recorded here.
