## v1.3.1-rc.8 (pre-release, qualification candidate)

Workspace version `1.3.1`. Supersedes `v1.3.1-rc.7` for new installs. Not a stable release. Not accepted on a device
or from a Russian network.

### Why rc.8
The first real two-host installation of rc.7 (a Berlin relay and a Helsinki exit, 2026-10-26) found that the
documented pairing pipe `pair issue-exit | pair accept-exit` did not work. rc.8 fixes that and the tooling around it.
Everything in rc.7 is otherwise unchanged.

### Changes since v1.3.1-rc.7
- **Pairing pipe fixed (`vpn-admin pair issue-exit` / `issue-hairpin`).** The apply path printed
  "sing-box reloaded and verified active ..." on stdout in front of the bundle JSON, so the other host rejected the
  bundle and a dedicated credential was left behind. Now only the bundle reaches stdout (progress goes to stderr).
- **No orphaned credentials.** The output is decided before the credential exists: a terminal, an existing file or
  an unwritable path is refused first; the file is reserved (new, mode 0600) up front. If delivery fails afterwards
  (full device, closed pipe) the credential just issued is removed again and a partial file is deleted.
- **Hiddify-core acceptance for relays** (`deploy/lib/hiddify_core_acceptance.py --mode relay`). Fetches only the
  pinned profile, verifies it holds exactly one exit route through the relay hop with nothing selectable that
  bypasses it, then runs Hiddify's own core and requires the exit's egress address. The default direct mode is
  unchanged. Subscription URLs are never printed: a malformed URL used to put the token into a traceback.
- **Docs**: install a specific candidate by pinned tag (`docs/INSTALLATION.md`); the pairing failure table covers
  delivery failures; IPv6-by-hostname evidence (`docs/qualification/2026-10-26/IPV6_BY_HOSTNAME.md`: not a defect,
  the probe used `curl -6` against an IPv4 loopback proxy).

### Compatibility
- No configuration, schema or credential changes. rc.7 -> rc.8 is an ordinary `update.sh --version` upgrade.
- Bundles produced by rc.7 are accepted by rc.8 (the bundle format is unchanged); an rc.7 exit still emits the extra
  stdout line, so install the same release on both hosts of a pair.
- AlmaLinux 9 is the supported OS. Ubuntu 22.04/24.04: best-effort (one real install each, not a support claim).

### Limitations (unchanged)
- No Russian-network, no native Android/iPhone Hiddify, no UDP/QUIC-through-relay evidence.
- The nested-Vision hang seen on a live relay is field-only and unexplained.
- Private-pilot egress exception: Google/YouTube may exit through the relay; all other traffic exits at the exit.
