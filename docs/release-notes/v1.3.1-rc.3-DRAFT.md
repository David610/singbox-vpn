release candidate exists because **v1.3.1-rc.2 and every earlier release contain defects that make nodes lose

## Not fixed / not verified (read before relying on this release)
* **YouTube Shorts cannot play from this node's IP** (both families refused). The hairpin mechanism is verified only
  in simulation; it needs an owner-authorized target (see `docs/operations/HAIRPIN_TARGET_QUALIFICATION.md`).
* **Native client acceptance is UNVERIFIED** (Hiddify iOS/Android/desktop, Shadowrocket, INCY, v2rayNG, NekoBox,
  Streisand). The real Hiddify core v5.0.3 and the pinned sing-box core pass loopback tests only.
* REALITY adds ~60-80 ms to each new connection with a remote decoy (I-60, owner decision); Hysteria2 +~2 ms.
* Reboot, external-network reachability, provider firewall, SSH key-only access: not verified (owner actions).
* CI has not run on this branch (nothing pushed). Ubuntu 26.04 is outside the supported tier.

## Upgrade
1. `sudo /opt/singbox-vpn/deploy/almalinux/update.sh --version v1.3.1-rc.3` (use a maintenance window: sing-box restarts, all connections drop; Hysteria2 clients may stall up to ~30 s on a real network).
2. `vpn-admin doctor --protocol --require-protocol` must report no `[FAIL]`; `nft list table inet arcana_egress_isolation | grep -c 'skuid !='` must print 0; `ip -6 neigh` must not show the gateway as FAILED.
3. Nodes updated *from* rc.2 or earlier: the update replaces the egress-isolation script; verify step 2.

## If the update is interrupted (power loss, SIGKILL, lost SSH)
`sudo /opt/singbox-vpn/deploy/almalinux/update.sh --recover` — it validates the transaction marker, then restores the
previous release, finishes a committed update, or clears leftovers; it refuses with an explicit message when automatic
recovery would be unsafe. Then re-run the update.

## Roll back a completed update
`sudo /opt/singbox-vpn/deploy/almalinux/update.sh --version <previous tag> --allow-downgrade` (transactional; it rolls
itself back if the older release fails its protocol check). Downgrading below the release that introduced
`public_ipv4/public_ipv6` requires removing those keys first and re-rendering (see `evidence/lifecycle/`).
